# UI/UX Rules
- Follow `docs/DESIGN_SYSTEM.md` and `design/tokens.css` exclusively.
- All pages must have complete loading, empty, error, permission and success states.
- Use consistent information architecture and predictable actions.
- Primary action is visually singular; destructive actions are separated.
- Tables support column labels, sorting affordance, filters, pagination and responsive fallback.
- Every form has labels, hints, validation and preserved input after recoverable errors.
- Use real example data from the seeded demo tenant; do not use lorem ipsum in visual reviews.
- Add Storybook story before or with shared component implementation.
- Mobile field actions require large touch targets and visible offline/sync state.
